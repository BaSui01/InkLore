# ADR-0020：Gin HTTP 入口与严格请求契约收敛

- **状态**：Accepted
- **日期**：2026-09-20
- **决策者**：用户本轮明确授权的 Gin 统一重构计划
- **关联任务**：INK-190、INK-191、INK-192、INK-200、INK-201
- **替代关系**：无；落实 ADR-0016/0018/0019，不改变公开 R1 契约

## 背景（Context）

七域虽然已经挂载 Gin，仍有重复 Body 读取、DTO 反射必填推断和独立 JSON 解析。Agent 存在缺依赖时信任身份头、缺幂等键直接执行的旁路。路径扫描与旧中间件造成多个技术入口。

## 决策（Decision）

1. Gin 仅位于 HTTP Transport 和技术基座。纯 strictjson 解析负责 UTF-8、重复键、数字精度、EOF 和深度；HTTP 负责 2MiB 限制、Content-Type、请求 Schema 和 DTO 解码。
2. 从现有机读契约生成嵌入资源及 method/Gin 路由模板/operationId 映射；启动离线编译、拒绝外部引用、缺失映射失败关闭。字段必填/可空/大小写/未知字段由 Schema 决定，不从 Go 标签推断。
3. Agent 正式构造必须具备完整服务、身份、幂等依赖。授权在重放前和事务内重验；CAS 留在首次业务执行内。
4. Gin 原生路由树负责 405 Allow；统一关联、白名单日志、无请求转储恢复和精确 CORS。显式可信代理配置，默认不信任转发头。
5. SSE 缓冲编码后检查 Write/Flush，使用单次写截止时间；断开只释放订阅。保留 ticket WS、PG 文件、标准 http.Server 和文件条件/范围响应语义。
6. 删除被替代消费者与实现，不增加兼容开关、数据库迁移或新控制器框架。

## 备选方案（Alternatives）

| 方案 | 优点 | 缺点 | 为什么未采用 |
| --- | --- | --- | --- |
| Gin binding 标签 | 简单、库内置 | 第二份必填定义，不能替代机读 Schema | 单一契约源要求 |
| 运行时加载仓库 Schema | 无生成步骤 | 依赖工作目录与文件，部署易漂移 | 二进制离线可复现 |
| 保留分域解析与兼容入口 | 改动少 | 安全规则持续分叉 | 用户明确要求删除重复机制 |

## 后果（Consequences）

输入拒绝规则一致，安全依赖缺失立即显现。代价是生成资产和路由映射必须随契约同步，并在启动时承担离线编译成本。模型输出只复用纯解析，保留独立 Schema 策略。

## 验证方式（Verification）

构建、vet、archguard、Schema 生成一致性、notes/skills；隔离 HTTP 探针覆盖严格 JSON、405/OPTIONS/CORS、代理、panic/SSE；真实隔离 PG/Redis 覆盖身份、幂等并发/撤权/回滚与文件/WS。缺少真实服务明确记录未验证，不将编译当作事务验收。
