# Agent Note: 离线迁移 LIVE 路径不能以样本代替旧库

Status: implemented

Task: INK-244
Scope: cmd/migrate/r1migration/executor.go、legacy_extract.go、r1_apply.go

## Problem

旧执行器即使指定旧库，仍打开连接后返回内置样本；目标写入返回 nil 却不执行任何语句，LIVE 可声称迁移成功。仓库的旧版迁移 DDL 并不含用户身份表，R1 目标又要求 bcrypt 密码哈希、归属身份、LLM 定价/策略版本和 Agent 运行快照；靠硬编码用户或丢弃不可兼容历史会把真实迁移伪装为零损完成。两个当前可连接的 InkLore 数据库都是 R1 结构，没有真实旧库。

## Decision

旧库模式经平台 GORM 连接，使用只读可重复读事务，先核查必要物理表和列，再取固定白名单字段，不抽取密钥正文；源不存在即失败。目标路径先校验数据集可信度，再在 GORM 单事务内校验迁移版本、空库、逐表写入和行数；身份、历史和不可转换字段缺失时一律拒绝写入。禁止在 LIVE 中启用样本、缺少不同源/目标库、跳过已失败门禁；verify-only 尚未实现就明确拒绝。此举是防止虚假成功，不代表已完成旧库零损转换。已有模拟样本只能作只读演练。

## Alternatives considered

直接把旧书全部归给 root 可以少做身份映射，但不同租户作者归属不可推断，也违反最小权限；给所有用户填固定密码哈希无法安全登录且伪造身份。仅写兼容的部分表虽然能产生成功行数，却丢弃章节历史、Agent/LLM 配置和使用记录。上述方案均未采用；等待真实旧库及可信迁移规则。

## Consequences

不可信或缺源的 LIVE 命令会在写入前失败，不能再返回成功假报告。旧库实体提取及18表目标写入代码已具备受限路径，但当前旧结构与 R1 字段不一致，不能跳过阻断；真正数据迁移依赖旧库和身份/版本映射。开发者不得用密码作为映射参数。

## Verification

`go build ./...`、目标 `go vet`、LSP 诊断通过；样本 `-dry-run=true` 退出0，样本 `-dry-run=false` 和真实模式无源均退出1；DBX只读核对 `ai_novel`、`inklore_r1` 均为 R1 表结构，不执行任何旧库或目标库数据写入。前述检查不等于真实全量迁移验收，INK-244 标记 blocked。未写测试文件或泄露凭据。
