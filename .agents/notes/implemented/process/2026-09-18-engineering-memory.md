# Agent Note: 工程记忆与 ADR、任务状态分工

Status: implemented

Task: INK-143
Scope: .agents/notes、三个项目技能、离线笔记门禁与CI

## Problem

INK-142 把局部取舍放入任务验收记录，便于首次落地，但跨任务检索长期约束不集中。用户明确要求像 DSH 一样增加 .agents/notes。现有 ADR 和 backlog 分别负责架构裁决与任务状态，工程记忆需要独立落点，避免重复权威。

改前检索核对了 [INK-142 交付](../../../../docs/skill-delivery-INK-142.md) 与 [来源适配](../../../skills/inklore-decisions/references/source-adaptation.md)：前者保留为历史事实，后者关于不建 notes 的活跃流程说明由本决定替代。开工时没有既有 notes。本条只交付工程流程，不宣称业务功能完成。

## Decision

[笔记规约](../../README.md) 定义四生命周期、六分类与固定头块。notes 保存实现因果并链接 ADR，backlog 唯一管理任务状态。三个 skills 执行改前检索、非平凡改动同批更新与历史追溯，机械改动无需笔记。

[离线工具](../../../../scripts/agent-notes.mjs) 校验结构、真实任务关联、本地链接和归档封印。implemented 才能归档，首次提出日期不变；源入站引用或迁移后死链未处理时拒绝移动。归档使用排他锁串行更新，保留恢复副本，禁止自动抢占残留锁。

哈希按LF规范化，跨平台换行不改变SHA-256。普通check验证工作树一致性，带 --base 的check对照Git历史manifest保护旧封印；CI取PR base SHA或push前SHA。真实归档清单为空，归档行为在隔离夹具验证，不为展示而伪造历史。工具不归档ADR、不安装上游看板或运行服务。

## Alternatives considered

- 继续把全部局部理由留在验收记录：改动少、符合初始交付，但用户要求可长期检索的工程记忆，分散记录无法满足，因此不选。
- 把全部ADR搬入notes：目录统一，但会混淆正式裁决与局部实现经验，且改变历史路径，因此保留ADR并链接。
- 直接安装完整上游工具及看板：功能丰富，但要适配任务编号、禁止测试文件和现有CI；选择范围明确的本地工具，代价是持续维护检查器。
- 仅校验当前哈希：实现简单，但正文与manifest一起修改可绕过；增加Git基线比较，同时明确首次引入与无基线的保护边界。
- 只在写入前复查manifest：能发现部分并行改动，但仍存在检查后竞争窗口；用排他锁覆盖读取、验证、写入和回滚，避免两个代理归档相互覆盖。

## Consequences

后续会话可以按机制查到失败路线和隐含约束，不依赖聊天记忆。ADR、notes、任务与设计各自有Owner，记录通过链接关联而非重复复制。

需要承担技能/规约/校验器同步维护，非平凡判断和理由真实性仍需评审。archived链接必须保持可解析；有已封印历史入链时保留被引用的活跃笔记，不能改封印解除阻塞。跨文件写入不是数据库事务，进程中断需核对恢复副本再处理残留锁。工具哈希不是签名，不能代替对CI和受信基线的仓库保护。
