验收日期：2026-09-18，北京时间。任务状态唯一来源为 [backlog](../../../../docs/backlog.md)。本报告覆盖 INK-177 离线数据迁移转换工具、UUIDv4 映射算法、正文确认与事实账本一致性核算、全量数据门禁、双端前端 bundlehash 校验及最终切换演练设计。**更正（INK-244）：当时的117项验收仅在内置样本的只读演练中通过，并没有执行旧数据库真实抽取或 R1 目标库落库；原 LIVE 路径会把样本当旧数据并空写入，不能据本报告判定真实迁移成功。现已改为旧表 GORM 抽取与不兼容数据 fail-closed，真实迁移仍因缺旧库与可信身份/历史映射而阻塞。**

### 实现与运行路径

- [离线迁移转换工具](../../../../cmd/migrate/r1migration/main.go)：独立于日常在线服务与基础 DDL 迁移工具，专为旧系统（Legacy）向 R1 全量 14+74 张表进行离线数据抽取、格式清洗、确定性映射与写入验证。
- [UUIDv4 确定性映射表](../../../../cmd/migrate/r1migration/mapping.go)：严格遵循 RFC 4122 与 R1 物理表 CHECK 约束（第 15 位为 '4'，第 20 位为 '8'/'9'/'a'/'b'）。通过加盐 SHA-256 命名空间算法，保证演练与实切时旧数据 ID 映射至完全一致的 R1 UUID，杜绝多次重放产生的 ID 漂移与外键悬空。
- [正文清洗与模型转换](../../../../cmd/migrate/r1migration/transformer.go)：
  - 清洗章节正文所有 Windows \r 回车符，满足 R1 约束 `position(E'\r' in body)=0`；
  - 精确计算 UTF-8 字符码点（Rune）字数与 SHA-256 内容哈希；
  - 针对旧库无卷散章，自动合成默认正文卷，严格满足 `content_chapters.volume_id NOT NULL` 约束；
  - 同步生成平台资源授权投影 `platform_resource_scopes` 与版本证明 `platform_resource_revisions`。
- [事实账本一致性核算引擎](../../../../cmd/migrate/r1migration/ledger.go)：
  - 核算每个已确认章节的 `current_version_id == confirmed_version_id` 与 SHA-256 哈希；
  - 将旧版 `fact_ledger` 记录平滑迁移至 `worldview_fact_ledger_events`，生成连续自增的 `seq` 与 `world_revision`；
  - 为每条事实事件生成独立加盐哈希载荷 `worldview_fact_payloads` 与有效头指针 `worldview_fact_heads`；
  - 针对缺乏显式事实事件的已确认章节，自动追加章节里程碑确认事件，确保出版级网文事实不可变溯源。
- [全量数据门禁验证器](../../../../cmd/migrate/r1migration/validator.go)：
  - 零遗漏核算（旧数据条目 = R1 导入条目 + 明确废弃条目）；
  - 全外键跨表引用可达性验证；
  - 租户作用域（Tenant Scoping）隔离验证，确保跨租户串扰记录为 0；
  - 全量 UUIDv4 格式物理约束复核。
- [双端静态资源指纹校验器](../../../../cmd/migrate/r1migration/bundlehash.go)：
  - 独立校验创作者工作台（Creator Studio :3000）与系统管理端（Admin Console :3001）的入口文件与静态 Bundle 哈希；
  - 严禁创作者工作台包含管理端入口 `admin.html` 或管理端专属路由，捍卫双端物理隔离铁律。
- [旧无用代码清理清单登记](../../../../cmd/migrate/r1migration/deadcode.go)：
  - 登记 4 类共 13 项待清理资产（旧 internal/novel 领域包、旧 000001~000018 迁移、7 张明确废弃数据表、旧废弃 HTTP 路由）；
  - 静态检查确认 7 个 R1 业务域无任何反向依赖 `internal/novel`。

### 旧库到 R1 最终切换演练步骤

依据 [系统交付与验收计划 (§4 旧库切换)](../../../../docs/system-design/18-DELIVERY-AND-ACCEPTANCE-PLAN.md)，生产环境切换必须严格遵循以下标准八步操作流：

```text
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ 1. 冻结与备份 │ ──> │ 2. 隔离建R1库 │ ──> │ 3. 离线全量ETL│ ──> │ 4. 门禁核算验 │
└──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘
                                                                       │
┌──────────────┐     ┌──────────────┐     ┌──────────────┐             ▼
│ 8. 旧库封存  │ <── │ 7. 流量切R1  │ <── │ 6. 增量短窗口 │ <── ┌──────────────┐
└──────────────┘     └──────────────┘     └──────────────┘     │ 5. 双端静态部署│
                                                               └──────────────┘
```

1. **第一步：旧库只读冻结与全量物理备份**
   - 在维护窗口开始前 15 分钟，将旧系统置为只读维护状态，停止后台 Agent 任务与定时 Worker；
   - 对旧 PostgreSQL 数据库执行只读快照与全量备份：`pg_dump -Fc -v -f inklore_legacy_pre_cutover.dump`；
   - 记录快照位点（LSN）与数据校验和。
2. **第二步：隔离创建目标 R1 生产数据库与 DDL 初始化**
   - 创建独立的 PostgreSQL 16 数据库实例（禁止与旧库混用相同库名或复用旧连接池）；
   - 执行 `go run ./cmd/migrate -cmd up`，严格按顺序应用 R1 基础表结构（`000001_platform.sql` 至 `000005_llm.sql`），确认 14 张平台基座表与全量 74 张表初始化就绪。
3. **第三步：执行离线数据映射与全量转换**
   - 启动转换引擎：`go run ./cmd/migrate/r1migration -legacy-dsn="..." -r1-dsn="..." -dry-run=false`；
   - 自动生成并持久化 `r1_migration_id_mappings` UUID 映射表；
   - 完成租户、用户、作品、卷、章节、版本、大纲、世界观实体的批量落库。
4. **第四步：账本一致性核算与数据安全门禁复查**
   - 运行校验程序对 R1 目标库进行一致性核验：`go run ./cmd/migrate/r1migration -verify-only=true`；
   - 确认正文版本确认率 100%、Worldview FactLedger 载荷 SHA-256 校验率 100%、外键与租户隔离合规率 100%。
5. **第五步：双端前端静态资源发布与指纹确认**
   - 生产环境构建 Creator Studio 与 Admin Console：`npm run build`；
   - 校验 `dist/` 与 `dist-admin/` 产物文件哈希，核对部署平台 CDN 缓存策略与 Nginx 指向。
6. **第六步：维护窗口最终增量同步（Catch-up Window）**
   - 在宣布正式切换前，抓取旧库在全量备份后产生的极少量增量变动，通过映射表增量补入 R1 库；
   - 确认两端数据总条数严格平衡（差异计数为 0）。
7. **第七步：流量切换、核心探针与可用性验证**
   - Nginx / Ingress 反向代理切换后端流量指向 R1 服务集群端口（29080）；
   - 前端静态站点切换指向新 Bundle；
   - 触发核心可用性探针：`GET /healthz`、`GET /readyz`、创作者登录态与作品大纲拉取测试。
8. **第八步：进入观察期与旧库冷备封存**
   - 保持 30 分钟现场灰度监视，持续观测应用错误率与 Redis/PG 负载；
   - 验证无误后，正式解除维护模式，旧库保持只读封存 30 天后按安全规程销毁。

### 回滚边界与数据安全性保证

#### 1. 严格单向流动红线（禁止逆向倒灌）
- **核心铁律**：R1 架构引入了不可变追加事实账本（FactLedger Events）、严格租户作用域、加盐载荷与 CAS 版本机制。**在切换至 R1 后产生的新增业务写入，绝不可逆向倒灌（Backflow）回旧库结构**。旧库字段设计（如缺少 volume 强制绑定、缺少版本树）无法容纳 R1 的高阶状态，逆向同步会直接破坏一致性。

#### 2. 分阶段回滚应急预案与时间窗
为应对切换过程中可能发生的不可抗力故障，制定清晰明确的阶段回滚决策树：

| 故障发生阶段 | 触发条件 | 回滚策略 | 数据安全性评价 |
| --- | --- | --- | --- |
| **阶段一：全量导入与验证期** (Step 1~4) | 转换脚本异常中断、门禁核对发现未通过项 | 立即终止迁移进程，丢弃 R1 临时数据库；旧库未修改，随时解除维护模式恢复旧系统服务 | **零风险**：旧数据未受任何写操作，数据完整度 100% |
| **阶段二：流量切换后 30 分钟内** (Step 7 观察期) | R1 API 发生大面积 5xx、核心鉴权异常，且**尚未产生任何作者确认正文写入** | 1. 立即回切 Nginx 流量指向旧服务集群；<br>2. 回切前端 CDN 指向旧版静态资产；<br>3. 标记 R1 目标库作废；<br>4. 旧库恢复读写服务 | **零数据丢失**：回滚窗口内仅有探针只读流量，无业务增量损失 |
| **阶段三：切换运行超过 30 分钟 / 已发生正文确认写入** | R1 发生局部非致命功能异常 | **严禁整库物理回退！**<br>立即启用热修复补丁或降级熔断策略。若必须紧急修复，仅提取 R1 库中新产生的 `content_chapters` 与 `content_chapter_versions` 导出为标准 NDJSON 归档文本包，通过补偿工具保留创作者心血 | **正文零丢失保障**：任何情况下绝不因回滚回滚掉创作者最新码字成果 |

#### 3. 旧库数据保全与脱敏
- 旧库只读冷备份保留周期为 30 天，存放于具有加密保护的备份存储介质；
- 满 30 天观察期且未发生任何追溯诉求后，依合规要求执行安全数据擦除（Purge）。

### 启动与使用约束

1. **生产部署授权约束**：离线转换工具默认强制启用 `-dry-run=true`。在未获得明确的生产维护窗口部署授权前，任何人员严禁在包含真实生产数据的数据库上以 `-dry-run=false` 执行。
2. **密钥与凭证安全**：迁移工具严格禁止在内存或日志中打印任何数据库密码、用户明文密码或 LLM 渠道 API Key。DSN 连接串日志输出已全面接入 `MaskDSN` 脱敏。
3. **不可抗力熔断**：若迁移过程中出现单次致命 SQL 异常，整个数据库迁移事务必须立即全面回滚（Rollback），严禁留下半成品脏数据。
