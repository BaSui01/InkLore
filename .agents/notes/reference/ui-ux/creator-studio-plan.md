# Creator Studio · 创作者体验优化蓝图

> INK-259 · 规划稿，不定义新 HTTP 协议。权威目标为[15 创作者 UI](../system-design/15-CREATOR-FUNCTION-UX-SPEC.md)；编辑器、状态与键盘以 [17](../system-design/17-DESIGN-SYSTEM-AND-ACCESSIBILITY.md)、[20](../system-design/20-FRONTEND-REUSE-AND-STATE-CONTRACTS.md) 为准。

## 1. 现有入口与目标能力

当前 [creator/App.tsx](../../../../frontend/apps/creator/src/App.tsx) 分派首页、编辑器、Agent 开书引导、大纲、世界观、节奏分析和登录/注册/找回。编辑器独立全屏，不在外层重复放导航栏。用户体验方案应保留这个沉浸式方向。

| 现有入口 | 当前代码组件 | 正式目标功能 / 当前限制 |
| --- | --- | --- |
| / | HomeRoute、BookCard、CreateNovelDialog | C01 书架与开书；项目其他资源不可从本地 mock 填充 |
| /agent-guide | AgentNovelGuideRoute | INK-236 正在实施的逐轮开书；真实 Agent 回合和确认仍需验收 |
| /editor?novelId=… | EditorRoute、PlainTextEditor、确认/质检/冲突弹窗 | C03 核心写作，关联 C04/C10/C12；当前 URL 不等于冻结目标的深链结构 |
| /outline | OutlineRoute | C02/C05 大纲与结构的部分页面入口 |
| /worldview | WorldviewRoute | C07–C10 角色、设定、图谱与事实的部分入口 |
| /analysis | AnalysisRoute | 当前节奏分析；不等同全部 C11–C13 灵感/工作流能力 |
| /login 等 | CreatorLoginRoute | Creator audience 的认证与安全回跳 |

C06 伏笔、C11 拆书灵感、C13 工作流、C15 审批、C16 文件、C17 检索、C18 统计、C19 设置与回收站等在 15 中有完整目标合同，但不能仅因后端某项有 API 就声称前端已具备对应独立闭环。页面扩展需先核对真实数据读写与用户权限，后续逐项验收。

## 2. 首页设计：更快进入写作

用户从书架应一眼完成三件事：找到上一部作品、开启新作品、理解作品的当前状态。首屏采用真实 BookGrid、清晰的一个“创建作品”主操作、轻量筛选和最近编辑信息。作品为空时显示引导而非伪造样本。作品卡片必须使用后端返回的 title、status、updated_at、word_count 等真实字段，并按照权限显示管理操作。

开书有两条明确路径：

- **手动开书**：CreateNovelDialog 根据 Content.CreateNovel 所需字段提交，成功获取真实 novel_id 后进入作品；网络重复点击使用幂等机制避免重复创建。
- **Agent 引导开书**：进入真实 /agent-guide，会话由后端持续管理；仅在模型、工具及策略可用时提供引导，作者明确确认后才调用 Content 创建作品。失败保留输入，不回退到“假 AI 进度”，并按 INK-236 的未验收状态提示。

无登录时首页只显示合法公共内容，不能泄露个人书架。账号切换必须清租户缓存与正在请求的旧结果。

## 3. 主场景：专注写作工作台

### 桌面结构线框（1440×1024 概念布局，非最终视觉图片）

~~~text
┌─────────────────────────────────────────────────────────────────────────┐
│ 返回书架  作品 / 章节       保存状态 · 最近保存时间      [保存] [专注]    │
├─────────────────┬──────────────────────────────────┬──────────────────┤
│ 卷 / 章节目录   │                                  │ 角色 / 设定       │
│                 │          章节标题                │                  │
│ 当前章节        │                                  │ AI 建议与上下文   │
│ 相邻章节        │       纯文本正文编辑区           │                  │
│ 结构快捷入口    │        原生 textarea             │ 运行状态 / 审阅   │
│                 │                                  │                  │
│                 │                                  │                  │
├─────────────────┴──────────────────────────────────┴──────────────────┤
│ 本地字数  ·  服务器修订  ·  离线保护  ·  冲突/恢复提示                   │
└─────────────────────────────────────────────────────────────────────────┘
~~~

结构宽度、正文宽度、检查器宽度及响应式降栏遵守 17：宽屏结构 240、正文建议 640–800、检查器 320；正文优先。当前 [EditorRoute](../../../../frontend/apps/creator/src/routes/EditorRoute.tsx) 已有章节、内容保存状态、AI 工作台、确认/质检/冲突弹窗与模型目录等状态，优化应逐步提取单一 EditorController 和通用可访问状态组件，不重写事实 Owner。

交互层级：

1. 章节正文始终是视觉焦点，使用原生 textarea；不改用富文本编辑器作为正文事实存储。
2. 页面顶部只突出“保存”。AI 扩展、事实确认、版本比较和质检是次级操作，不抢占写作空间。
3. 左栏承载结构树与章节跳转；未保存内容切章前提示。窄屏变互斥抽屉，切换不得覆盖当前输入。
4. 右侧展示真实角色/设定上下文、当前 Run、待审批和候选改写；无数据时不伪造建议，离线时禁危险命令。
5. 专注模式隐藏左右栏与非核心导航，但保留保存、错误、恢复告警及离开入口。
6. 在 320 CSS px 和 400% 缩放下保持正文一列，保存条不得遮住输入。

### 保存、恢复和冲突

依[15 §C03](../system-design/15-CREATOR-FUNCTION-UX-SPEC.md)，标题与正文为两个独立的受控保存步骤：变化的标题先提交并获取 revision，变化的正文按最新 revision 提交。必须出现“标题已保存、正文未保存”的部分成功状态，而不能一次性显示全部成功。

- 正文 GET 失败时禁止将空字符串写回服务器；有效的空正文与读取失败必须区分。
- 保存返回 409 进入三方比较（服务器最新版、本地未保存稿、原基线），不得静默覆盖。
- 网络断开可本地继续输入，显示恢复保护状态；联网先获取当前 revision 再提示合并。
- 章节切换、租户切换与异步回复关联 tenant/user/novel/chapter/generation；不把前一章的响应写到新章。
- 中文输入法组合态、Unicode 码点偏移、段落空行和连续撤销不得破坏正文。
- 只有真实服务器成功确认才能显示“已保存”，不能用计时器或发起请求代替事实。

## 4. AI、质检、事实与用户控制

- Agent 的 Run、SSE 事件、审批和澄清各有独立真实状态。断线根据 run_id 与 Last-Event-ID 续订，不再次 POST 新 Run 来假装重连。
- 选择文本发起 AI 操作必须附 source_revision/content_hash；结果先入候选审阅，作者明确接受后再走 Content.SaveBody。AI 不能绕过 Content/Worldview 写入事实。
- 合规报告按章节来源修订定位，旧报告标 stale；问题定位基于 Unicode 码点而非重复词猜测。建议净化不直接覆盖正文。
- 章节事实确认是 Content.ConfirmChapter 受控命令；必须读到正文版本、世界修订与待确认事实，缺任一数据禁提交。
- 未配置有效任务策略、模型或工具时显示真实缺失与重试路径，不展示按钮假执行或乐观成功。

## 5. 用户端视觉语言

依据 [17 视觉规范](../system-design/17-DESIGN-SYSTEM-AND-ACCESSIBILITY.md)：Creator 使用纸张语义 surface/paper、适合长文本的衬线正文字体和简洁的蓝色交互状态，不另建一套主题。正文 18px / 1.8 为默认，用户可在规定范围内调整字号与行高，设置只影响偏好不写入作品正文。共享图标使用 Lucide，禁装饰性 Emoji。全部可见 UI 文案和 aria-label 从 i18n 词条生成。

空态只提供真实下一步；离线、部分失败和过期数据应可见但不轰炸。图谱与节奏图必须有同权限的可访问表格替代视图，不使用动画伪造业务进展。

## 6. 建议分批与验收

1. **Creator-01 书架/开书**：真实多作品、空书架、重复创建幂等、未登录/跨租户；Agent 引导按 INK-236 留待专项端到端验收。
2. **Creator-02 编辑核心**：纯文本输入、IME、Ctrl/Cmd+S、写入双步骤、500/409/断网、本地恢复、切章不串稿；工作台各断点屏幕截图。
3. **Creator-03 AI 审阅/质检/事实**：SSE 重放、同 run 恢复、人工采纳、事实 revision、权限收回，严禁 Agent 自动写正文。
4. **Creator-04 大纲/世界观及其余目标页**：按 15 号合同逐条补齐真实页面、统一状态/键盘体验，附操作与后端 owner 证据。

图片生成、语音、协同实时编辑、自动外部投稿和订阅支付不在当前 R1 范围；**本蓝图不加入这些假入口**。
