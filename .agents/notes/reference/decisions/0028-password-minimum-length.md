# ADR-0028：密码最低长度调整为六个字符

- **状态**：Accepted；按用户明确要求调整
- **日期**：2026-09-27
- **决策者**：BaSui
- **关联任务**：INK-232
- **替代关系**：部分替代 ADR-0016 与 ADR-0021 的密码最低长度条款；bcrypt cost、最大字节数、认证流程与账号边界不变。

## 背景（Context）

Creator/Admin 当前前端、Go 身份服务、机读 API Schema 与 R1 身份契约统一要求密码至少 12 个字符。用户要求全系统改为 6 个字符以上。密码长度是全局身份契约，必须同步前端提示、注册/重置/成员创建/改密校验、登录输入 Schema 与实施文档，避免接入层、应用层和持久化边界出现不同判据。

## 决策（Decision）

密码策略统一为至少 6 个 Unicode 字符且最多 72 个 UTF-8 字节；bcrypt cost 保持 12。所有新密码入口使用同一服务端验证，前端提示和严格 Schema 采用相同字符下限。已有更长密码继续有效，不要求重置。

## 备选方案（Alternatives）

| 方案 | 优点 | 缺点 | 为什么未采用 |
| --- | --- | --- | --- |
| 保留 12 字符下限 | 更大的离线猜测空间，维持原冻结条款 | 不满足用户对当前登录与设置流程的明确要求 | 用户明确要求系统统一接受至少 6 字符 |
| 降低 bcrypt cost | 缩短弱密码验证延迟 | 降低所有账号的哈希计算成本，扩大离线猜测速度 | 无需改变密码校验的哈希成本来放宽长度下限 |

## 后果（Consequences）

**正面**

- 6 至 11 个字符的新密码可以通过Creator/Admin及所有后端密码写入路径。
- 现有较长密码和 72 UTF-8 字节上限保持不变。

**负面 / 代价**

- 相较 12 字符下限，允许更容易被猜测的密码；登录限流、bcrypt cost 12 和现有会话控制仍必须保留。
- 前端、服务端、严格请求Schema和R1契约需同批调整；Schema只校验码点长度，后端继续额外限制UTF-8字节数。

**需要长期承担的义务**

- 新增密码设置、引导、邀请或重置入口必须复用6..72规则，不得新增低于6字符的旁路。
- 不得把本次示例凭据写入源码、文档、日志或默认配置；初始密码仍由运维显式注入/交互输入。

## 验证方式（Verification）

检查 `identity.ValidatePassword` 对5、6字符及超过72 UTF-8字节的输入边界；严格Schema中的密码 `minLength` 为6、`maxLength` 为72；前端登录、注册、找回密码和国际化提示一致。执行API设计检查、嵌入Schema编译、双端构建、`go build ./...`、archguard、i18n与工程笔记检查。不新增任何测试文件；未执行的真实身份数据库/浏览器密码提交必须明确记为未验证。
