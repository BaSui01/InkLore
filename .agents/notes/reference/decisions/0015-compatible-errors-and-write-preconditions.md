# ADR-0015：兼容现有错误契约与写入前置条件（提案）

- **状态**：Rejected — 用户要求整体重构，旧路由/封包兼容路线不采用；R1依据ADR-0016/0017。本文保留原提案与取舍，不是施工契约。
- **日期**：2026-09-18
- **决策者**：待项目负责人评审；本文不宣称已接受
- **关联任务**：INK-124（设计），INK-117/118、INK-125/126/127（实施）
- **替代关系**：无；遵守 ADR-0001、0002、0007、0009、0014，不改域边界或通信归属

## 背景

当前 `internal/platform/response/json.go` 返回字符串 `code`、本地化 `message`、可选 `data/trace_id`；前端 `shared/api/client.ts` 却把失败压成只有 message 的 Error。设计目录中的数字 code、`ERR_*`、UUID 运行 ID、GET 订阅流不等于当前运行契约。保存、生成、确认遇到断网时，用户无法可靠区分“未执行”与“执行成功但响应丢失”；无条件重试会覆盖新正文或重复计费。

## 拟议决策

优先保留既有 `/v1` 线协议，并以可选结构化错误信息、写入版本前置条件和操作幂等逐步补齐恢复能力。具体错误码与状态表见 [14 分册](../system-design/14-ERROR-HANDLING-AND-RECOVERY.md)。

1. 不把 `code: string` 原地改为数字；不要求现有调用方读取 `error_code`。成功仍为 `success`。新增错误码使用字符串，发布前登记 HTTP 状态、所属域、恢复动作与双语词条。HTTP 状态表达传输结果，工具 `success=false` 由应用层转换为失败视图。
2. 前端归一化错误保留 HTTP 状态、code、trace_id、白名单 data 及取消/网络/协议错误分类。未知 code 有通用本地化兜底，不能因此弹出服务端栈或丢失未保存正文。只读请求与带副作用命令采用不同重试策略。
3. Content 写正文拟加入 `expected_revision`。同一事务内比较当前 revision，保存正文并生成新版本；不匹配返回 409，禁止先写后检查。确认与回滚也需绑定所审阅版本。是否复用现有版本号或增加独立锁列，由 INK-126 检查每条写路径后在实施 ADR 中补证据，不能仅凭前端版本列表推断。
4. 写命令拟支持 `Idempotency-Key`。幂等作用域包含认证租户、主体、操作类别和资源；请求规范化摘要不相同则冲突，相同则重放原结果或返回执行中，不启动第二次生成。存储与业务提交必须有一致性保证；记录保留期、敏感载荷、容量和回收策略在实施前定案。当前不存在全局 HTTP 幂等保证。
5. 生成流保持请求级 SSE。断流不能自动重发 POST；先显示结果未知并查询已有运行记录。事件续传、后台持久任务、取消确认需要独立实施契约，不能由客户端计时器或仅关闭连接来伪造。既有审批按 ADR-0009 由本人审批本人，不以管理员页面存在推导代批权限。
6. 为避免一次迁移破坏旧客户端，先交付客户端兼容解析，再按操作启用新字段；版本前置条件从可选观测到必填的时间点须单独发布迁移说明。缺少前置条件时不能声称已有并发保护。

## 备选方案

| 方案 | 优点 | 代价 / 不采用理由 |
| --- | --- | --- |
| 把 `/v1` 全面改为数字错误码及新路由 | 与旧蓝图形式一致 | 已有客户端、流解析、脚本都需破坏性迁移，且不解决数据竞争 |
| 前端只加 toast 与禁用按钮 | 改动小 | 多窗口、重放和响应丢失无法靠按钮解决 |
| 保留字符串契约并分阶段增加恢复语义（推荐） | 可与当前代码逐步联调，旧响应可读 | 需要登记表与兼容期，幂等/版本的持久化设计需补齐 |

## 后果

正面：保护创作内容、避免把断流误判成功、保留已有客户端；错误提示有明确动作。代价：结构化错误映射与版本冲突界面增加维护成本；幂等与重放涉及持久化和数据保留，不能仅添加请求头。

本文不批准新表、队列实现、认证供应商、跨管理员审批。七域边界按已接受的 ADR-0014 执行，本提案不改变该决策。新设计中的对应能力维持提案状态；现有 ADR 与代码兼容规则在评审期间继续生效。

## 验证与进入 Accepted 的条件

- 用真实路由请求核对现有成功/400/401/404/409/429/503封包；旧客户端仍能读取成功结果。
- 两个窗口读同 revision，A 保存后 B 保存被拒，B 的本地正文仍可复制与合并。
- 同幂等键同载荷在响应丢失后重放只写一个版本/只启动一个运行；不同载荷冲突；不同租户互不查询。
- 推流已产生文本后断开，界面不显示完成，不自动触发第二个 POST；取消与晚到成功的竞态以服务器终态为准。
- 评审明确版本来源、幂等存储/保留期、旧客户端兼容窗口；逐条证据落入 backlog 后再改状态。
