# ADR-0006：平台自签 HS256 令牌与认证默认策略

- **状态**：Accepted
- **日期**：2026-09-17
- **决策者**：项目负责人
- **关联任务**：INK-007
- **替代关系**：无

## 背景（Context）

此前所有 HTTP 接口**完全裸奔**：没有认证、没有租户绑定。而 `platform/auth` 已存在完整的主体（Principal）与权限模型，`tenantcontext` 已提供租户上下文载体 —— 缺的是"令牌如何进来、默认是否强制"这两个契约。

约束：

- 项目要求密钥只从环境变量注入（ADR-0004），不能为了认证引入一个必须落库的会话表；
- 前端正在并行开发，接口突然强制认证会直接打断联调；
- 但生产构型绝不能因为"忘记配置"而裸奔。

## 决策（Decision）

1. **仅支持平台自签 HS256 令牌**，手写最小实现（`crypto/hmac` + `sha256` + base64url），不引入外部 JWT 依赖：
   - 显式校验 `alg == HS256`，拒绝 `none` 等算法降级；
   - 签名比较使用 `hmac.Equal`（常数时间）；
   - 校验 `exp`；载荷只含 `sub / tid / uid / roles / iss / iat / exp`。
2. **签名密钥只从环境读取**：`JWT_SECRET`，未设置时回退 `ENCRYPTION_KEY`。
3. **认证模式 `AUTH_MODE`，默认随环境**：
   - 生产（`APP_ENV=production`）默认 `required`；
   - 其余环境默认 `disabled`（若请求携带令牌仍会解析并绑定，便于联调）。
4. **`required` 模式下强制要求租户**：令牌缺少 `tid` 直接 401，避免"认证了但没隔离"。
5. **`required` 但未配置密钥 → 进程拒绝启动**，而不是静默放行。
6. **公开路径**：`/healthz`、`/readyz`、`/v1/architecture` 免认证。
7. 签发工具 `cmd/tokengen`（本地联调与运维排障），密钥同样只从环境读取。

## 备选方案（Alternatives）

| 方案 | 优点 | 缺点 | 为什么未采用 |
| --- | --- | --- | --- |
| 引入 golang-jwt 等成熟库 | 少写代码、生态验证充分 | 为本项目最小需求引入新依赖 | 需求仅限于 HS256 校验，自实现约 120 行且可完整审计 |
| 会话表 + 不透明 token | 可服务端吊销 | 需要建表与清理，且必须落库 | 依赖数据库，当前 M1 尚未落地；且与"密钥只从环境注入"取向不符 |
| 默认一律强制认证 | 最安全 | 直接打断前端联调与本地演示 | 靠环境默认值区分，生产仍是强制 |
| 全部接口免认证（维持现状） | 零改动 | 生产裸奔 | 不可接受 |

## 后果（Consequences）

**正面**

- 生产构型默认强制认证，忘记配置会拒绝启动而不是静默裸奔。
- 本地与前端联调不受影响（开发默认放行）。
- 令牌校验逻辑可完整审计，无隐藏依赖。

**负面 / 代价**

- 无服务端吊销能力：令牌在有效期内始终有效（默认 24h）。需要吊销时必须引入会话表或短 TTL + 刷新。
- `AUTH_MODE=disabled` 下携带无效令牌只记 WARN 并放行 —— 这是刻意的联调妥协，生产不会走到。

**需要长期承担的义务**

- 接入认证中心（OIDC）后，本实现退化为兼容层，需新增 ADR 说明迁移路径。
- 新增受保护路由必须挂载在 `/v1` 组下，否则不会经过认证中间件。

## 验证方式（Verification）

以 `AUTH_MODE=required` 启动后实测 11 项：

- 无 Token / 伪造 Token / 缺 `tid` / 过期 Token → 401，且 code 分别为
  `auth_token_required`、`auth_token_invalid`、`auth_tenant_missing`；
- 有效 Token → 200；`/v1/auth/whoami` 回显主体、租户与**请求上下文中的租户**（隔离前提）；
- `/healthz`、`/readyz`、`/v1/architecture` 免认证可用；
- 开发环境默认（不设 `AUTH_MODE`）无 Token 仍可访问。
