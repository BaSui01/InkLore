# ADR-0021：R1.x 认证扩展正式纳入契约

- **状态**：Accepted；用户明确要求“保留扩展，另立 R1.x 契约变更”
- **日期**：2026-09-20
- **关联任务**：INK-209、INK-203
- **替代关系**：部分替代 ADR-0016 第5条的禁止公开注册约束；其余身份、租户隔离和角色边界继续有效。

## 背景

现有认证实现包含验证码、创作者注册及密码找回，但冻结操作映射没有这些入口。严格请求 Schema 启动校验正确拒绝该漂移。用户选择保留扩展并正式修订契约，不允许借跳过映射检查继续运行。

## 决策

新增 GET /v1/auth/captcha、POST /v1/auth/captcha/verify、POST /v1/auth/register、POST /v1/auth/forgot-password、POST /v1/auth/reset-password 的严格机读请求/响应与错误声明。注册成功返回200 Session，并设置creator专属刷新Cookie；仅创建独立租户及creator身份，不接受角色、tenant_id或管理权限输入。登录tenant_id可省略，由已验证账户的现有活动成员关系选择，随后仍检查应用角色及租户状态。

登录、注册和找回保留可选验证码，但一旦提供必须成对且有效；挑战有效期180秒，一次校验即消费。验证码单独验证不颁发身份，也不能替代业务请求自身的挑战。注册及重置使用既有统一密码规则（12字符下限、72 UTF-8字节上限），不继续保留8字节的旁路。注册重复账户使用409 auth.account_unavailable；重置无效令牌使用400 auth.invalid_token。

这些公开认证命令与原有login/refresh同属凭据交换，不纳入会保存完整响应的通用幂等缓存。账户创建、会话创建及审计仍原子提交；密码修改与会话撤销必须在同一事务。重置令牌必须避免事务失败提前消费及并发双消费。

现有密码找回没有邮件投递器，不能声明生产已发送。保留开发环境的短期令牌回显流程（响应no-store，禁止日志记录）；未接入投递服务的非开发环境返回503 platform.dependency_unavailable。开发响应的sent=false明确没有邮件投递，expires_in=900，dev_token仅在开发环境且账户有效时出现。现有进程内短期挑战/重置令牌重启失效、不能跨副本共享；该限制须记录为开发实现边界，不宣称生产找回可用。本次不引入邮件供应商、外部存储或新数据库迁移。

更新源契约、派生产物、冻结清单及文档，保留变更前冻结清单。数据库主版本升级另行核实目标版本和实际连接，不与本裁决混合。

## 备选与代价

删除未冻结扩展可保持旧R1不变，但用户明确选择保留。将未实现的邮件发送标为成功会误导用户，因此在投递器完成前明确返回依赖不可用。短期内存令牌降低本轮存储变更范围，但需要后续生产投递与多副本方案，不能当作生产验收通过。

## 验证门禁

源契约生成一致、离线Schema编译和完整路由映射通过；验证验证码成对要求、注册密码边界、角色注入拒绝、注册事务、登录tenant选择、重置失败/并发/撤销会话与环境响应差异。执行build/vet、架构护栏和notes/skills检查；数据库连接缺失时如实记录未验证，不以编译替代事务证据。
