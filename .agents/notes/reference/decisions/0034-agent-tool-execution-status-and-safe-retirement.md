# ADR-0034：Agent 工具执行状态显式暴露与历史定义安全退役

- **状态**：Proposed
- **日期**：2026-09-29
- **决策者**：待产品与架构评审
- **关联任务**：INK-246
- **替代关系**：拟补充 R1 Agent 治理 API 的工具响应字段与删除语义；不改变运行历史不可变原则

## 背景（Context）

原定义删除仅对未引用版本物理删除；引导会话等历史外键会拒绝删除。工具治理列表的 `enabled` 只表示租户数据库中的配置开关，而当前组合根既未调用 `NewScheduler`，也未装配 `NewToolService`，因此不能据此宣称工具可被 Agent 执行。用户要求管理界面可删除智能体与工作流，并只展示真实可执行的 Agent Tools。原 R1 契约未定义执行器状态投影；直接在页面写静态工具清单违反真实数据约束。

## 决策（Decision）

提议按租户及预期修订号退役定义和工作流的可变头，保留不可变版本与运行、节点、引导会话的引用；可选目录立即过滤已删除头，运行从冻结版本读取。软删资源的唯一机器键仍保留，不由重播种悄悄恢复。

提议在 Admin 工具响应保留只读 `execution_status`：只有 Worker 与对应执行器已在同一个运行进程装配、租户启用并且工具不可变版本的 Schema 与处理器合同匹配时才返回 `available`，其他情况返回 `not_bound`。本轮仅装配受控只读 `platform_utc_now`：处理器真实读取 UTC 时间，其他工具、MCP 及旧启发式工具都不得伪报可用。新工具仍须逐项完成租户权限、参数验证、真实执行与故障恢复；不能修改前端文案或将状态常量设为 `available` 代替接线。

## 备选方案（Alternatives）

| 方案 | 优点 | 缺点 | 为什么未采用 |
| --- | --- | --- | --- |
| 级联删除被引用版本和会话 | 用户立刻看不到资源 | 丢失运行证据并损坏在途任务 | 违反冻结版本与可审计历史约束 |
| 继续只返回引用409 | 不需改持久化语义 | 用户无法清理可选目录 | 无法解决本次问题 |
| 将登记配置或遗留工具类直接标为可执行 | 无需构建运行链即可展示卡片 | 虚报功能、实际调用失败 | 违反零假功能原则 |

## 后果（Consequences）

定义与工作流可退出可选目录，历史版本保留；旧 key 因唯一索引无法直接重建，种子重播需报告跳过。当前仅能在服务端真实装配 Worker、当前租户登记并启用工具时看到一项 `platform_utc_now` 可执行能力；其余配置另行展示为不可用，不能将它们算入可执行数量。冻结 API 响应扩展正式纳入 R1.x 基线前仍需评审；真实模型选择工具、执行回执及失败竞争也仍需穿透验证。

## 验证方式（Verification）

核对同租户已引用定义的 CAS 删除、重复删除和旧修订号拒绝；删除后目录不再出现、旧 Run 冻结版本仍可读，种子重跑不复活。以真实管理会话 GET 工具列表核对已装配且已登记的 `available` 与未装配配置的 `not_bound`，只允许前者进入 UI 可执行区；模型调用必须以冻结工具版本运行并留下真实 tool.started/completed 与观察回执。Go 与 Admin 编译、生成 Schema、i18n、架构护栏仅是静态门禁，不替代真实 PG/HTTP/Worker 验收。
