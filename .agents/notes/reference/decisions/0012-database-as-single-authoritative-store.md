# ADR-0012：数据库是唯一权威存储，内存档位需显式开启

- **状态**：Accepted
- **日期**：2026-09-17
- **决策者**：项目负责人
- **关联任务**：INK-108
- **替代关系**：无（收窄 [ADR-0011](./0011-production-config-delivery.md) 与 M1 验收 ④ 中「断库降级」的**默认值**，能力本身保留）

## 背景（Context）

M1 验收标准第 ④ 条要求「断库启动给出明确错误与降级策略，而非 panic」，实现方式是：**未配置** `DATABASE_DSN` 时，开发环境打印一条 WARN 并降级为内存仓储；生产环境直接拒绝启动。

这条默认值在实践中制造了一个比它解决的问题更大的问题：

- 开发档位的启动日志里只有一行 WARN，而服务、接口、界面**全部照常工作**。作者可能写完整整一卷，直到进程重启才发现正文从未落库。
- 新增能力（卷 / 场景 / 章节版本，INK-067/069）在两条存储链路上各写一份实现，内存链路的行为差异（例如删卷是否解绑章节）只能靠人肉对齐；默认走内存等于默认在验证一条与生产不同的路径。
- 本项目的产品形态是**单机/私有部署写作工具**（D1 决策），本地库里放的就是作者的真实创作，不存在「开发环境可以随便丢」的正当性。

约束与相关红线：

- [AGENTS.md](../../../../AGENTS.md) §1：`internal/novel` 是作品事实的**唯一权威 Owner**——权威数据必须落在持久化存储上，「进程内存里的副本」不构成权威。
- 与 [ADR-0005](./0005-no-fabrication-without-provider.md)（未配置 Provider 时默认拒绝生成）同构：**宁可明确失败，也不要静默降级**。
- 已有 `LLM_BUILTIN_FALLBACK` 的先例：危险档位必须显式开启。

## 决策（Decision）

**数据库是唯一权威存储。未配置 `DATABASE_DSN` 时进程拒绝启动，包括开发环境；只有显式设置 `ALLOW_MEMORY_STORE=true` 才允许降级为内存仓储，并打印「不得用于真实创作」的醒目告警。**

具体做法：

1. `storage.allow_memory_store`（环境变量 `ALLOW_MEMORY_STORE`）新增于平台配置，**默认 false**。
2. 组合根 `openDatabase` 的判定顺序：生产环境缺 DSN → 拒绝（原有行为）；开发环境缺 DSN 且未显式开启 → 拒绝；显式开启 → 打印 WARN 并返回内存档位。
3. 内存仓储实现**不删除**：它们是离线联调与「无外部依赖跑通接口形状」的工具，但必须显式启用。
4. 拒绝启动时的错误信息必须写清三件事：缺什么、为什么拒绝、如何显式开启。

## 备选方案（Alternatives）

| 方案 | 优点 | 缺点 | 为什么未采用 |
| --- | --- | --- | --- |
| 保持现状（开发环境静默降级 + WARN） | 开箱即跑，无需任何依赖 | 与产品形态冲突：数据没落库却一切正常；内存与 SQL 双实现的行为差异被默认掩盖 | 用户明确要求「全部存储要在数据库」，且静默降级已在实测中暴露语义分叉 |
| 彻底删除内存仓储实现 | 语义唯一，没有第二条链路 | 失去离线联调能力；本机无 Docker 时无法起服务；改动面大于收益 | 保留能力、只改变默认值是同等安全且更小的改动 |
| 默认连本地 PostgreSQL，失败才报错 | 少一个配置项 | 仍是隐式行为，且 DSN 凭据不该被猜 | 显式优于隐式 |

## 后果（Consequences）

**正面**

- 「数据是否落库」不再依赖读日志：没库就起不来，误用不可能发生。
- 新能力只需保证 SQL 链路正确，内存链路退化为显式选择的联调工具。
- 与 ADR-0005 形成一致的失败哲学：危险降级必须显式开启。

**负面 / 代价**

- 本地开发首次启动必须准备数据库；`scripts/dev-stack.ps1`（INK-107）把这步压成一条命令。
- M1 验收 ④ 的「无 DSN 可启动」不再是默认行为，复现该验收需显式设置 `ALLOW_MEMORY_STORE=true`。已在 roadmap M1 条目中标注。

**需要长期承担的义务**

- 任何新增的持久化能力都**必须**提供 SQL 实现；内存实现是可选项（仅用于联调），不得成为默认路径。
- 新增任何「危险降级」开关时沿用本 ADR 的形态：默认关闭 + 显式开启 + 醒目告警。

## 验证方式（Verification）

1. 不设 `DATABASE_DSN` 且不设 `ALLOW_MEMORY_STORE` 时启动 `cmd/server` → **退出码非 0**，错误文本包含「数据库是唯一权威存储」与「ALLOW_MEMORY_STORE=true」。
2. 不设 `DATABASE_DSN` 但设 `ALLOW_MEMORY_STORE=true` → 进程启动，日志出现「内存仓储档位已显式开启」WARN，`/readyz` 的 `database=disabled`。
3. 设 `DATABASE_DSN`（`scripts/dev-stack.ps1` 起的本地栈）→ 启动成功，`/readyz` 的 `database=ok`。
4. 代码位置：`internal/platform/config/config_types.go`（字段）、`config_env.go`（环境变量）、`internal/app/app.go` 的 `openDatabase`（判定顺序）。
