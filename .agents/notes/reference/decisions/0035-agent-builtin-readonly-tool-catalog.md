# ADR-0035：Agent 工具只读内置目录，不开放在线配置

- **状态**：Proposed
- **日期**：2026-09-29
- **决策者**：用户明确要求；契约冻结仍待评审
- **关联任务**：INK-247
- **替代关系**：拟替代 R1 管理端 A10 可配置工具 CRUD 及 ADR-0034 中“已登记配置”可见的部分；定义/工作流删除与运行冻结版本规则不变

## 背景（Context）

此前工具页一半展示可用能力、一半展示租户“已登记配置”，还允许管理员新建、修改、删除工具。即使限制运行时执行器，这仍把项目代码内置工具表现为业务人员可以任意配置的资源，违背用户明确要求。代码里只有真正安装了 Handler 的能力才可以作为工具展示；静态卡片、数据库里自定义 key 或未装配的旧工具类不能变成实际执行器。历史 Agent 定义与运行仍通过数据库保存冻结工具版本，不能直接删除版本表造成历史失效。

## 决策（Decision）

1. Admin 使用只读 `GET /v1/agents/builtin-tools`。服务端从实际 Go `ToolExecutor` 的 handler 注册表枚举代码内置的名称、描述和 Schema；当前租户的可用状态另经已启用的内部冻结版本核验。数据库配置不决定有哪些工具能出现在目录中。
2. 管理页面工具区只有目录和状态，不提供工具配置列表、新建、编辑、停启和删除按钮；智能体定义与工作流的治理行为保持原样。已有定义绑定版本编辑时保留原绑定，不将机器 key 猜成 UUID。
3. 对外移除 `POST /v1/agents/tools`、`PUT/DELETE /v1/agents/tools/{tool_id}` 的路由和机读 operation。旧 `GET /v1/agents/tools` 与详情仅保留供内部版本/历史查询；未知写方法由统一的 405/Allow 机制拒绝，不提供绕过前端的后门。部署侧幂等 `admin seed-tool` 仅用于注册程序内置能力的租户冻结版本，不是作者或管理员的在线配置入口。

## 备选方案（Alternatives）

| 方案 | 优点 | 缺点 | 为什么未采用 |
| --- | --- | --- | --- |
| 仅隐藏工具按钮 | 前端变动小 | API 仍可写任意配置；用户可绕过 UI | 不符合“不能配置” |
| 只展示数据库配置但锁定编辑 | API 无需新增 | 展示项仍受数据库自定义 key 控制，不等于代码中的真实工具集合 | 不能证明项目内置能力 |
| 删除全部版本存储 | 完全无数据库配置感 | 会破坏已运行和在途任务的冻结版本与审计 | 历史仍需保留 |

## 后果（Consequences）

工具增减需要代码实现、审查、部署及内部版本同步，不再依赖管理 UI 保存任意 Schema；管理员只能看代码内置能力及当前租户是否具备可执行版本。新租户若未完成内部版本播种，目录仍列出已安装 handler，但状态为 `not_bound`，不能显示为“可执行”。冻结 API 资产的响应增量及写操作移除须经过 R1.x 裁决；不能将本提案假装为早期 R1 冻结事实。

## 验证方式（Verification）

已认证管理端 GET 返回代码注册的唯一工具，篡改数据库中额外工具 key 不得添加到内置目录；未播种/禁用的租户不得返回 available。工具写端点无论前端是否展示都应返回 405 且无数据库变化，GET 仍按管理员身份校验。Go/Admin 构建、请求 Schema 生成检查、双语词条与页面浏览器核对；实际模型工具调用另按 Agent Run 运行链验证。
