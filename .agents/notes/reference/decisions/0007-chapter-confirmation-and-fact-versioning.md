# ADR-0007：章节确认制与事实版本化

- **状态**：Accepted
- **日期**：2026-09-17
- **决策者**：项目负责人
- **关联任务**：INK-016
- **替代关系**：无

## 背景（Context）

平台的核心承诺是「长篇不崩设定」。这要求两件事同时成立：

1. **事实只有一个权威来源**：作品域（~~internal/novel~~）是事实的唯一 Owner，
   Agent 只能读上下文、产出草稿与建议（AGENTS.md 第 2 节）；
2. **事实可回溯、可演进**：设定会随剧情推进而合法变化（如「主角突破了禁制」），
   不能简单覆盖或删除旧值，否则事后无法回答「这个设定是哪一章改的、为什么改」。

此前的状态是：~~fact_ledger~~ 表与 Fact 模型存在，但**没有版本化、没有一致性校验**，
任何写入都直接生效，草稿也可以绕开事实账本。

## 决策（Decision）

1. **章节确认制**：草稿（~~draft~~）不能直接生效。必须经
   ~~POST /v1/novels/:novelID/chapters/:chapterID/confirm~~ 确认后，
   章节状态才变为 ~~confirmed~~，事实才入账。
2. **事实以「提议」进入**：确认请求携带 ~~facts~~ 提议列表，由作品域校验后落账。
   Agent 无法直接写事实账本。
3. **版本化采用「置失效」而非删除**：同一事实（同类别 + 同 key）取值变化时，
   旧行 ~~is_active=false~~ 保留，新行写入并记录 ~~source_chapter_id~~。
   账本因此始终可回溯到来源章节。
4. **一致性门事务性批量判定**：确认前用现有活跃事实评估整批提议；
   **只要有冲突就整批拒绝、零写入**，不做部分入账。
5. **冲突通过业务结果而非 error 传递**：应用层返回
   ~~ConfirmResult.Conflicts~~，传输层据此回 ~~409~~ 与结构化冲突清单。
   error 通道只承载服务端异常（未找到、存储失败）。
6. **授权覆盖需显式声明**：~~allow_override=true~~ 时才允许用新值覆盖既有活跃事实，
   并保留被覆盖的历史行。

## 备选方案（Alternatives）

| 方案 | 优点 | 缺点 | 为什么未采用 |
| --- | --- | --- | --- |
| 直接覆盖旧值（UPDATE） | 表结构最简单 | 丢失设定演进历史，无法回溯 | 与「可回溯来源章节」的验收直接冲突 |
| 冲突通过 error 返回 | 调用方少检查一个字段 | error 无法承载结构化清单，只能塞进 message 字符串 | 前端需要逐条展示「哪条设定与哪一章冲突」 |
| 部分入账（无冲突的先写） | 容错性好 | 账本进入半吊子状态，后续判定基准被污染 | 事实账本的完整性优先于单次请求成功率 |
| 用 LLM 判断正文是否违背设定 | 语义理解更强 | 不确定、不可复现、成本高 | 当前只做确定性的账本级校验；正文级审校属审校 Agent 职责（INK-015） |

## 后果（Consequences）

**正面**

- 事实账本永远可回答「当前生效值是什么」与「它由哪一章引入」。
- 冲突在入账前被拦下，不会出现两套互相矛盾的设定同时活跃。
- Agent 无法绕过作品域写事实，事实权威边界在代码层面成立。

**负面 / 代价**

- 写入路径变长：一次确认涉及多次读写，调用方需处理 409。
- 冲突判定是**账本级**的（同 key 不同值），无法发现「正文写的和设定不符」这类语义冲突——
  那属于一致性审校 Agent 的职责。
- 历史行会持续累积，需要后续归档/压缩策略。

**需要长期承担的义务**

- 任何新增的事实写入路径都必须经过一致性门，不得直接调仓储 Create。
- 若未来引入「软删除事实」，必须区分「失效（被新值取代）」与「作废（设定被撤销）」两种语义。

## 验证方式（Verification）

以真实 PostgreSQL 实测 18 项断言：

- 首次确认：无冲突、写入 1 条事实、~~source_chapter_id~~ 指向来源章节、章节状态变 ~~confirmed~~；
- 同值重复确认：识别为 ~~unchanged~~，不冲突也不重复入账；
- 冲突场景：拦下并返回含旧值/提议值/来源章节的清单，**零写入**，账本仍只有 1 条活跃事实；
- 授权覆盖：旧事实失效 + 新事实写入，账本呈现「1 条活跃 + 1 条历史」；
- 跨租户确认返回 404；空 key 返回 400。
