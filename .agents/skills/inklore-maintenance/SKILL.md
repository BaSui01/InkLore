# InkLore 维护与排障

## 1. 固定事实与范围

阅读 [AGENTS](../../../AGENTS.md)、用户当前要求及 [当前架构](../../../docs/architecture.md)，区分诊断、修复、发布准备与实际部署的授权。

- 记录环境、时间、版本、症状、复现步骤和预期结果；保留相关请求标识和最小日志。
- 检查工作区差异及已有 Issue/PR，复用正在进行的任务，避免覆盖并行修改。
- 沿真实入口、服务、数据或供应商调用、组合根及前端消费方定位；不以历史设计替代当前实现。
- 日志与证据脱敏，避免输出完整环境变量、凭据、请求正文和作者私有内容。

GitHub Issues/Milestones 是当前任务状态来源；旧 INK/backlog 与历史验收仅供追溯。维护技能不新增固定批准步骤，当前用户授权持续有效。

## 2. 缩小故障范围

| 症状 | 优先核对 |
| --- | --- |
| 生成无输出、中断或重复计费 | Provider、渠道/模型、真实协议、Run/Job、取消及上游结果是否确定 |
| 页面保存后未生效 | 请求字段、事务、回读、缓存以及实际运行消费者 |
| 权限或跨租户异常 | 主体/session、资源 Owner、仓储 scope、文件和 SSE 的授权路径 |
| 正文、版本或事实不一致 | 版本检查、事务边界、确认流程及失败后的持久化结果 |
| 前端空白、进度不符或输入丢失 | 网络、控制台、状态恢复和对应 API |
| 就绪失败或任务不能恢复 | 实际探针、依赖、迁移、租约、checkpoint 与进程日志 |

先验证能区分原因的假设。证据不足时增加针对性的诊断信息；确定根因后做最小修复。不能靠假内容、默认成功、静默回退或关闭安全检查隐藏错误。

## 3. 修复与运行恢复

实施参考 [开发交付](../inklore-development/SKILL.md)。复用现有错误、日志和组件；只对涉及的调用链、失败路径与并发/权限边界增加必要回归验证。

依赖升级核对实际行为、协议及兼容变化。无行为补丁不强制新增 ADR；重要取舍参考 [决策记忆](../inklore-decisions/SKILL.md)。

生产写入、迁移、恢复或模型调用按本次授权处理。部署前核对当前脚本、目标环境、迁移连续性和回滚边界；不要从“排查”推断破坏性操作已获批准。

已获发布授权时执行并核验实际版本、healthz、readyz 与代表性路径。备份存在不等于恢复演练成功，应用回退不代表数据库迁移可安全回退。

## 4. 文档与历史

按 [资料路由](../inklore-development/references/doc-routing.md) 读取本次相关文档。代码与文档冲突时确定事实和需求后修正受影响内容，不将旧 accepted ADR 或阶段计划当永久约束。

当前能力区分完整实现、部分实现、缺失和证据不足；运行验收另记。历史材料不自动证明当前版本通过，配置声明和包可达也不能证明业务功能有效。

## 5. 验证与交接

按 [验证矩阵](../inklore-development/references/verification.md) 选择检查，重放原故障并验证正常路径。缺服务、模型或浏览器时明确未验证，记录真实命令、结果和阻塞。

必要时使用 [复盘模板](templates/incident.md) 保留影响、根因、修复和恢复证据；只有值得长期保留的内容才进入工程笔记。

交付说明修复结果、证据、仍存风险与后续任务。任务状态只更新已授权的 GitHub 工作项，不另建平行状态表。
