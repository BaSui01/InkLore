# InkLore 维护与排障

## 入口与范围

先读 [AGENTS](../../../AGENTS.md)、[R1设计入口](../../../docs/system-design/00-INDEX.md) 与 [契约基线](../../../docs/system-design/00-CONTRACT-BASELINE.md)，再读 [architecture](../../../docs/architecture.md) 与 [backlog](../../../docs/backlog.md)，并按 [工程记忆规约](../../notes/README.md) 检索该机制已有的活跃与否决笔记。按 [文档路由](../inklore-development/references/doc-routing.md) 加载相关设计与决策。实际修复使用 [开发交付](../inklore-development/SKILL.md)，架构取舍使用 [决策管理](../inklore-decisions/SKILL.md)。

明确是只读诊断、局部修复、发布准备还是已授权的实际发布。先从当前会话确认授权范围；不要重复索取已有授权。生产写入、数据恢复与有费用的模型调用按任务范围处理，不能从“排查”推断可执行破坏性操作。

## 1. 确定症状和基线

登记 INK 任务，记录环境、版本、时间、请求标识、复现步骤、预期与实际结果。读取 git diff，区分已有修改和本次修复。禁止输出完整环境变量、配置秘密和原始用户正文。

- healthz 反映进程存活；readyz 反映已配置依赖就绪。具体判据读实际 handler，不凭历史文档断言。
- 追踪入口、处理器、应用服务、Port、数据库或模型供应商、组合根和前端消费方。
- 配置从声明、默认值、环境覆盖、校验、装配、消费方到可观察结果逐层核对。“能保存”与“运行采用”分别验证。
- 核对目标基线与实际路径；历史 /v1/novels、七域目标路由或不同 SSE 入口不能混作同一个接口。

## 2. 缩小故障范围

| 症状 | 优先核对 | 不能采取的捷径 |
| --- | --- | --- |
| 生成无输出 / 中断 | Provider配置、路由与容量、HTTP/SSE错误、取消、run终态 | 返回模板正文掩盖故障；盲重试收费生成 |
| UI已保存但不生效 | 请求字段、事务、GET回读、实际配置消费者 | 本地缓存成功提示替代真实落库 |
| 数据串租户 / 权限异常 | 主体上下文、资源Owner、每次仓储作用域 | 放宽鉴权作为临时修复 |
| 确认或版本不一致 | 正文版本、事实Owner、事务边界、失败回滚 | 直接跨域改表；改写已确认账本 |
| 前端空白或假进度 | 对应Creator/Admin入口、网络与控制台、API能力 | 用静态业务数据/setTimeout兜底 |
| 就绪失败 | 依赖配置、网络、迁移、资源耗尽及日志 | 关闭探针冒充服务恢复 |

一次只验证一个可判定假设。证据指向范围外问题时登记新 INK，不顺手改动无关域。尽量在隔离开发环境复现。

## 3. 修复、发布与回滚

修复先确定验收与既有约束，不因代码“不优雅”删除历史妥协。依赖升级先判断行为、格式和外部依赖契约变化；补丁级无行为变更无需新建 ADR，真正选型变更按 ADR-First。

发布准备读 [运维与发布恢复](../../../docs/system-design/13-DEVOPS-OBSERVABILITY-AND-OPERATIONS.md) 与 [实时任务恢复](../../../docs/system-design/21-REALTIME-JOBS-AND-RECOVERY.md)：版本标识、构建产物、配置注入、迁移向前/向后兼容、备份可恢复性、就绪探针、停止条件和回滚步骤。准备完成不等于已经部署。数据库迁移不可默认随应用版本安全回退。

实际发布已授权时执行并验证版本、healthz、readyz 和代表性业务路径；记录真实命令与结果。备份存在不等于恢复验证完成。不要在文档中存令牌或未经脱敏的响应。

## 4. 文档巡检与工程记忆

按任务范围核对 AGENTS → 有效 ADR → R1基线 → API/DDL机读契约 → 领域/UI分册；再对照 architecture 与 backlog 的实施证据，不能用旧实现限制目标设计：

- 当前事实只写现状与验证边界，历史原因链接 ADR；不要复制 OpenAPI 清单。
- 设计中的接口、DDL、恢复机制与SLO标清目标；无实测不得写成已运行。
- 失效路径和入站链接同批修正；Accepted ADR 正文保持原样。
- 任务表的真实行优先于旧计数快照；发现统计漂移登记任务，不凭猜测更新总数。
- 配置面、包可达性、业务正确性是三个不同检查维度。

运行 [验证矩阵](../inklore-development/references/verification.md) 中相关命令；故障修复重放原始触发条件与正常路径。使用 [复盘模板](templates/incident.md) 收集证据，把值得防止重犯的根因和取舍沉淀到 `.agents/notes/implemented/bug-fix/`，按 [已实施模板](../inklore-decisions/templates/note-implemented.md) 编排并链接复盘证据；校验笔记，汇报遵循 INK → 状态 → 变更 → 证据 → 风险。
